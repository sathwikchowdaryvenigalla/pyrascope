# PyraScope – Technical Prototype (Milestone 4: frontend ⇄ live backend)

The React frontend now requests MODIS + VIIRS observations from the FastAPI backend
(`/api/harmonization/compare` and `/summary`, backed by Google Earth Engine) and draws exactly what comes back.
Nothing is simulated. If the backend is down or returns nothing, the UI says so instead of showing placeholder data.

## Run (two terminals, from the project root)

**Backend**

    python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
    pip install -r backend/requirements.txt
    cp .env.example .env                                   # set GEE_PROJECT_ID
    python -m backend.authenticate_gee                     # one-time browser sign-in
    uvicorn backend.main:app --reload --port 8000

**Frontend**

    npm install
    npm run dev                                            # http://localhost:5173

`VITE_API_BASE_URL` (in `.env`, default `http://localhost:8000`) is the single backend address the app uses.
The backend's `CORS_ORIGINS` must include the frontend origin (default already allows `localhost:5173`).

## Tests

    PYTHONPATH=. python -m unittest discover -s backend/tests -t .   # existing backend unit tests
    npm test                                                          # data layer + component render smoke test

Frontend tests use *contract fixtures* generated by the real backend formatting code
(`PYTHONPATH=. python tests/frontend/make_fixtures.py`). They are synthetic, are never imported by the app, and are not NASA data.

## How the app uses the API

| Endpoint | Used for |
|---|---|
| `GET /api/gee/status` | Earth Engine connection status shown in the header and search card |
| `GET /api/harmonization/compare?include_observations=true&max_details=2000` | Observations with coordinates, candidate pairs, unmatched ids, per-source retrieval info |
| `GET /api/harmonization/summary` | Cross-check of totals (served from the backend cache right after `compare`) |

Notes
* The spec's `/api/gee/health` does not exist in the backend; `/api/gee/status` and `/api/health` are the real equivalents.
* `/api/gee/modis-test` and `/api/gee/viirs-test` return small samples only, so the app does not use them for display.
* Date range and region changes are sent with **Retrieve observations** (each query is a heavy Earth Engine call).
  Satellite (MODIS / VIIRS / both), matching (all / candidates / unmatched) and calendar-date filters are applied instantly to the data already retrieved.
* Limits mirror the backend defaults: ≤ 31 days, ≤ 10° per bounding-box side, ≤ 5000 pixels per source, ≤ 2000 listed records per request.
  When the API truncates a list the UI says so and marks affected matching status as "unknown".
* Counts are observation **records**, not unique fires. Pairs are **candidate matches** (potential relationships), not confirmed fires.

`src/data/demoObservations.js` is the old simulated generator. It is no longer imported anywhere and is kept only for reference.
